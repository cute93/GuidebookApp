# WorkLog — 작업 기록 및 이력서 반영

완료된 작업을 `work-logs/` 에 상세 기록하고, 이력서(`my_career_data.md`) 반영 여부를 판단합니다.

## 실행 절차

### 1단계 — 작업 내용 수집

사용자에게 아래 세 가지를 질문합니다:

1. **배경**: 왜 이 작업을 했나요? (문제 상황, 요청 배경)
2. **상세 내용**: 무엇을 어떻게 했나요? (기술 스택, 의사결정 과정, 어려웠던 점)
3. **결과**: 어떤 성과가 있었나요? (정량적 지표, 비즈니스 임팩트)

### 2단계 — 작업 로그 파일 작성

`work-logs/YYYY-MM-작업명.md` 형식으로 파일을 생성합니다. (오늘 날짜 기준)

파일 구조:
```
# [작업명]

**날짜:** YYYY-MM-DD
**프로젝트:** [프로젝트명]
**소요시간:** [예상 시간]

## 배경

## 상세 내용

## 결과 및 성과

## 기술적 의사결정

## 회고
```

### 3단계 — 이력서 반영 판단

아래 기준 중 하나 이상 충족 시 `my_career_data.md`에 반영합니다:

| 기준 | 설명 |
|---|---|
| 정량적 성과 | 수치로 표현 가능한 개선 (성능 X%, 시간 단축 등) |
| 기술적 깊이 | 아키텍처 결정, 트레이드오프 분석 포함 |
| 조직 임팩트 | 팀·서비스·비즈니스 수준 영향 |
| 면접 스토리 | STAR 구조로 설명 가능한 경험 |

**미반영 항목** (로그만 기록): 일상 운영 업무, 개인 학습, 성과 불명확 사항

### 4단계 — 이력서 반영 실행 (해당 시)

- `my_career_data.md` 파일을 읽고 기존 프로젝트가 있으면 해당 섹션을 보강합니다.
- 새 프로젝트면 새 섹션을 추가합니다.
- 변경 이유를 한 줄 코멘트로 남깁니다.

### 5단계 — README.md 업데이트

`work-logs/README.md`의 로그 인덱스에 새 항목을 추가합니다:

```
| YYYY-MM-DD | 작업명 | 프로젝트 | 이력서반영여부 |
```

파일이 없으면 헤더와 함께 새로 생성합니다.

### 6단계 — git 커밋

변경된 파일들을 스테이징하고 커밋합니다:

```
git add work-logs/ my_career_data.md
git commit -m "log: [작업명] 작업 기록 추가"
```

이력서 미반영 시:
```
git commit -m "log: [작업명] 작업 기록 (이력서 미반영)"
```

## 완료 후 출력

작업이 끝나면 아래 형식으로 요약합니다:

```
✔ 작업 로그: work-logs/YYYY-MM-작업명.md
✔ 이력서 반영: O / X (사유: ...)
✔ 커밋: [커밋 해시]
```
